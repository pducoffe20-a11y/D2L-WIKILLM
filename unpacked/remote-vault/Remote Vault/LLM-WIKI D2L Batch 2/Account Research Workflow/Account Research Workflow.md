# Account Research Workflow — Enhanced (Context-Engineering Pass)

**Status:** Proposed enhancement of the existing workflow
**Base documents:** Quick Start Guide, Workflow, Workflow Automation script (2026-08-02)
**Applied skills:** `context-engineering:project-development`, `context-engineering:tool-design`, `context-engineering:filesystem-context`

This document explains what changed, why, and gives you drop-in replacement files. It does not restate the original workflow's business content (segments, playbooks, proof points) — that stays as-is. It fixes the *mechanics* of the pipeline.

---

## 1. What's actually broken in the current script

Before enhancing anything, a manual trace of `account-research.sh` surfaces two silent-failure bugs — worth fixing regardless of any architecture upgrade:

1. **Every heredoc uses `<< 'EOF'` (quoted delimiter).** Quoting the delimiter disables shell variable expansion inside the heredoc. So `01-public-research.md`, `02-d2l-angle.md`, and `README.md` are all written with the *literal strings* `COMPANY_NAME`, `CONTACT_NAME`, `RESEARCH_DATE`, `SEGMENT_TYPE` in them — the script never actually substitutes the real company name anywhere in the templates, despite computing `$COMPANY`, `$NAME`, `$SEGMENT`, `$TIMESTAMP` at the top.
2. **The embedded Python block interpolates `$OUTPUT_DIR` as a Python string literal** (`output_dir = '''OUTPUT_DIR'''`), not a bash substitution — same class of bug, Python side.

Net effect: today, running the script produces four files that all say "COMPANY_NAME" and "RESEARCH_DATE" verbatim, requiring a full manual find/replace before the templates are usable. This alone likely eats a chunk of the "2–3 hours" estimate in the Quick Start Guide.

The enhanced script below fixes this with unquoted heredocs (`<< EOF`) plus `envsubst`/sed-based substitution so the bug class can't recur silently.

## 2. Reframing as a pipeline (project-development)

The original workflow already has the right instinct (`INPUT → vault search → related work → public research → D2L angle → OUTPUT`) but conflates a **deterministic pipeline** with a **manual research task** in a way that makes it hard to tell what's automatable vs. what genuinely needs a human/agent.

Applying the canonical `acquire → prepare → process → parse → render` shape:

| Stage | Original workflow step | Deterministic? | Current state |
|---|---|---|---|
| **Acquire** | Vault search, related-work grep, Firecrawl website crawl | Yes (calls out) | ✅ partially automated (vault + related-work only) |
| **Prepare** | Templating input into research doc skeletons | Yes | ✅ automated, but broken (see §1) |
| **Process** | Reading vault docs, synthesizing D2L angle, writing public research narrative | **No — this is the LLM/human judgment step** | ❌ currently manual, unstructured, no cost/time tracking |
| **Parse** | Extracting fit level, ACV estimate, buying committee from the written docs | Yes (if Process stage outputs are structured) | ❌ doesn't exist — README fields are hand-typed |
| **Render** | Final README + package assembly, commit | Yes | ✅ manual only |

The single biggest structural gap: **Process (Stage 3) has no explicit contract.** The original workflow tells a human "read the top 3 vault docs, extract questions/outcomes/proof points, write them into 02-d2l-angle.md" — but that's exactly the shape of task an agent (Claude, via the Task tool) should own end-to-end, with a *structured output contract* it must satisfy, rather than "go read files and hope you extract the right things."

### Fix: give Stage 3 a structured output contract

Instead of "populate 02-d2l-angle.md free-form," require the agent (or human) producing it to emit a machine-checkable frontmatter block first, then prose. This makes Stage 4 (Parse) trivial and gives you a queryable index across all account research over time — you can't currently answer "show me every account we scored HIGH fit in associations" without opening every folder.

```yaml
---
company: "Wisconsin Technology Council"
segment: "technology council"
fit: HIGH          # HIGH | MEDIUM | LOW
estimated_acv_low: 50000
estimated_acv_high: 150000
sales_cycle_months: 4
value_drivers: ["non-dues-revenue", "operational-efficiency", "platform-consolidation"]
proof_points_used: ["ISC2", "South-University", "CMA"]
vault_sources: ["Association Discovery Framework.md", "Association Buyer Outcomes Matrix.md", "Business Case Toolkit.md"]
research_status: DRAFT   # DRAFT | READY_FOR_REVIEW | VALIDATED
last_updated: 2026-08-02
---
```

This single addition unlocks a `render` step nobody currently has: a portfolio-level rollup across `research/*/README.md` (pipeline hygiene, priority triage, ACV totals) generated by grepping frontmatter instead of re-reading every file.

## 3. Filesystem as state machine (filesystem-context)

The workflow already uses the filesystem correctly in spirit (`research/{company}-{date}/`), but it's missing the **idempotency signal** that makes file-system-as-state-machine actually pay off. Right now there's no way to tell, from the filesystem alone, whether a given account's research is:
- freshly scaffolded (templates only, not started)
- in progress (public research done, D2L angle not)
- complete and validated
- stale (>90 days, needs proof-point refresh — the workflow already calls this out as a rule but has no mechanism to check it)

### Fix: stage-completion markers + a status file

Add a `.stage` file per completed stage (empty marker files, following the "check file existence" pattern from filesystem-context):

```
research/{company}-{date}/
├── .stage-acquired         # vault + related-work search done
├── .stage-prepared         # templates generated
├── .stage-processed        # public research + D2L angle written by human/agent
├── .stage-parsed           # frontmatter extracted & validated
├── .stage-rendered         # README finalized, ready for outreach
├── vault-search-results.json
├── related-work-segment.txt
├── 01-public-research.md
├── 02-d2l-angle.md
└── README.md
```

A one-line `status.sh` script (included below) can then answer "what's the state of every account in flight" by listing which `.stage-*` files exist per folder — no parsing required, which is exactly the point of file-existence-as-idempotency-check.

This also fixes the **"reuse existing research" advanced-usage case** from the Quick Start Guide, which currently says "copy vault findings from previous research" with no mechanism — now you can `grep -l 'segment: "technology council"' research/*/02-d2l-angle.md` to instantly find every prior account in the same segment, using the frontmatter added in §2.

### Fix: scratch directory for large tool outputs

`vault-search-results.json` can grow large (10+ full vault doc matches with metadata). Per the filesystem-context "tool output offloading" pattern, the *summary* (top-3 titles + confidence) should be what a human/agent sees first — full JSON stays on disk for `jq`/`grep` drill-down, which the Quick Start Guide already does correctly (`jq '.results[0:3]'`). No change needed there — just noting it's already following the pattern well and should stay that way rather than getting "improved" into dumping the full JSON into a chat context later.

## 4. Consolidating the tool surface (tool-design)

The current workflow exposes the process as ~6 manual sub-steps a human executes one at a time (run script → read JSON → grep vault docs → copy into template → fill public research → fill README → commit). Per the consolidation principle — "if a human can't say definitively which tool to use, an agent can't either" — this should collapse into fewer, higher-level actions with unambiguous triggers, especially if you're going to delegate any of this to an agent (which the "wiki-LLM brain" framing suggests you are).

### Proposed consolidated commands

| Command | Replaces | Contract |
|---|---|---|
| `account-research.sh new "Name" "Company" "Segment"` | Steps 1–3 (vault search, related work, template gen) | Idempotent — safe to re-run; skips stages with existing `.stage-*` markers unless `--force` |
| `account-research.sh status [company-slug]` | Manually `ls -lt research/` and eyeballing | Returns one line per account: slug, stage, fit (if parsed), last-updated, staleness flag |
| `account-research.sh validate <company-slug>` | The manual "Output Quality Checklist" in the Quick Start Guide | Runs the checklist as a script: checks frontmatter present & complete, checks proof-point dates <90 days, checks all `[To be researched]` placeholders removed |
| `account-research.sh rollup` | Nothing today — new capability | Greps frontmatter across all `research/*/README.md`, emits a portfolio table (fit distribution, total pipeline ACV, stale-research count) |

This gives an agent (or you) four unambiguous entry points instead of a loose sequence of bash/python/manual-edit steps, each with a clear "when to use" — which is exactly the tool-design consolidation test.

## 5. Fixed & enhanced automation script

Drop-in replacement — fixes the heredoc bug, adds stage markers, adds frontmatter scaffolding, adds `status` and `validate` subcommands.

```bash
#!/bin/bash
# account-research.sh — Enhanced Account Research Workflow Automation
# Usage:
#   ./account-research.sh new "FirstName LastName" "Company Name" ["Segment"]
#   ./account-research.sh status ["company-slug"]
#   ./account-research.sh validate "company-slug"
#   ./account-research.sh rollup

set -euo pipefail

RED='\033[0;31m'; GREEN='\033[0;32m'; YELLOW='\033[1;33m'; BLUE='\033[0;34m'; NC='\033[0m'
VAULT_DIR="unpacked/remote-vault-d2l/Remote Vault - D2L"

# ---------------------------------------------------------------------------
cmd_new() {
    if [ $# -lt 2 ]; then
        echo -e "${RED}Error: Insufficient arguments${NC}"
        echo "Usage: $0 new \"Name\" \"Company\" [\"Segment\"]"
        exit 1
    fi

    NAME="$1"
    COMPANY="$2"
    SEGMENT="${3:-professional association}"
    TIMESTAMP=$(date +%Y-%m-%d)
    COMPANY_SAFE=$(echo "$COMPANY" | sed 's/[^a-zA-Z0-9-]/-/g' | tr '[:upper:]' '[:lower:]')
    OUTPUT_DIR="research/${COMPANY_SAFE}-${TIMESTAMP}"

    echo -e "${BLUE}=== Account Research: $COMPANY ($SEGMENT) ===${NC}"
    mkdir -p "$OUTPUT_DIR"

    # --- ACQUIRE ------------------------------------------------------------
    if [ ! -f "$OUTPUT_DIR/.stage-acquired" ]; then
        echo -e "${BLUE}[acquire] Searching D2L Sales Brain vault...${NC}"
        VAULT_SCRIPT="$VAULT_DIR/scripts/brain_search.py"
        if [ -f "$VAULT_SCRIPT" ]; then
            python3 "$VAULT_SCRIPT" "$SEGMENT" --json > "$OUTPUT_DIR/vault-search-results.json" 2>/dev/null \
                || echo '{"results": []}' > "$OUTPUT_DIR/vault-search-results.json"
        else
            echo -e "${YELLOW}  Warning: vault script not found, writing empty result${NC}"
            echo '{"results": []}' > "$OUTPUT_DIR/vault-search-results.json"
        fi

        echo -e "${BLUE}[acquire] Searching local research repository...${NC}"
        {
            find research/ -maxdepth 2 -name "*.md" -type f 2>/dev/null \
                | xargs grep -l "$SEGMENT" 2>/dev/null || true
            if [ ${#COMPANY} -gt 5 ]; then
                find research/ -maxdepth 2 -name "*.md" -type f 2>/dev/null \
                    | xargs grep -l "$COMPANY" 2>/dev/null || true
            fi
        } | sort -u > "$OUTPUT_DIR/related-work-segment.txt"

        touch "$OUTPUT_DIR/.stage-acquired"
        echo -e "${GREEN}  ✓ acquire stage complete${NC}"
    else
        echo -e "${YELLOW}[acquire] Already complete, skipping (use --force to redo)${NC}"
    fi

    # --- PREPARE (templates, with REAL substitution) -------------------------
    if [ ! -f "$OUTPUT_DIR/.stage-prepared" ]; then
        echo -e "${BLUE}[prepare] Generating templates...${NC}"

        # NOTE: unquoted heredoc delimiters below (EOF, not 'EOF') so that
        # $COMPANY / $NAME / $SEGMENT / $TIMESTAMP actually interpolate.
        # This fixes the silent bug in the original script where every
        # generated file contained the literal string "COMPANY_NAME".

        cat > "$OUTPUT_DIR/01-public-research.md" << EOF
# Public Research: $COMPANY

**Contact:** $NAME
**Date:** $TIMESTAMP
**Segment:** $SEGMENT

## Company Profile

### Organization Information
- **Company Name:** $COMPANY
- **Industry/Sector:** [To be researched]
- **Website:** [Add URL]
- **Geographic Scope:** [Local/Regional/National/Global]
- **Organization Type:** [Association/Enterprise/Nonprofit/Government/etc.]

### Size & Scale
- **Members/Employees:** [To be researched]
- **Annual Revenue:** [To be researched]

### Business Model
- **Primary Revenue Stream:** [To be researched]
- **Secondary Revenue (Non-Dues):** [To be researched]
- **Member Benefits/Products:** [To be researched]

## Leadership & Key Contacts
- **CEO/Executive Director:** [To be researched]
- **CFO/Finance Lead:** [To be researched]
- **VP Education/Learning:** [To be researched]
- **CIO/Technology Lead:** [To be researched]
- **Primary Contact:** $NAME

## Recent News & Strategic Initiatives
- [Add recent news item]

## Current Technology & Platforms
- **Current Platform:** [Moodle/Canvas/Custom/Unknown]

## Inferred Opportunities

Based on public research and industry patterns for $SEGMENT organizations:

### Potential Pain Points
- [Add specific pain points from research]

### Growth Opportunities
- [Add opportunities identified in strategic announcements]

## Research Sources

| Source | URL | Date Accessed |
|--------|-----|---|
| Company Website | [URL] | $TIMESTAMP |
| LinkedIn Company Page | [URL] | $TIMESTAMP |

---
**Status:** DRAFT
**Last Updated:** $TIMESTAMP
EOF

        cat > "$OUTPUT_DIR/02-d2l-angle.md" << EOF
---
company: "$COMPANY"
segment: "$SEGMENT"
fit: MEDIUM
estimated_acv_low: 0
estimated_acv_high: 0
sales_cycle_months: 0
value_drivers: []
proof_points_used: []
vault_sources: []
research_status: DRAFT
last_updated: $TIMESTAMP
---

# D2L Positioning: $COMPANY

**Date:** $TIMESTAMP
**Segment:** $SEGMENT

## Key D2L Value Drivers
1. [Value Driver 1 — problem / D2L solution / proof point]
2. [Value Driver 2]
3. [Value Driver 3]

## Buyer Outcomes Matrix

| Metric | Industry Baseline | D2L Target | D2L Enabler |
|--------|-------------------|-----------|------------|
| [Metric 1] | | | |

## Stakeholder-Specific Messaging

### VP Education / Director of Learning
**Discovery Questions:**
- [Question from vault discovery framework]

### CFO / Finance Lead
**Discovery Questions:**
- [Question from vault discovery framework]

### CIO / Technology Lead
**Discovery Questions:**
- [Question from vault discovery framework]

## Relevant Customer Proof Points

### Case Study 1: [Similar Company Name]
- Outcome: [quantified result]
- Relevance: [why this applies to $COMPANY]
- Source: [vault reference + external-use posture]

## Competitive Context
- **$COMPANY Likely Platform:** [educated guess]

## Business Case Framework
### ROI Drivers & Payback
- Driver 1: [description]
- Payback Timeline: [typical months]

---
**IMPORTANT:** Update the YAML frontmatter above (fit, ACV range, sales_cycle_months,
value_drivers, proof_points_used, vault_sources, research_status) as you complete
this document — the \`validate\` and \`rollup\` commands read it.
EOF

        touch "$OUTPUT_DIR/.stage-prepared"
        echo -e "${GREEN}  ✓ prepare stage complete${NC}"
    else
        echo -e "${YELLOW}[prepare] Already complete, skipping${NC}"
    fi

    # --- PROCESS (human/agent step — not scriptable, just scaffold README) --
    if [ ! -f "$OUTPUT_DIR/README.md" ]; then
        cat > "$OUTPUT_DIR/README.md" << EOF
# Account Research: $COMPANY

**Contact:** $NAME
**Date:** $TIMESTAMP
**Segment:** $SEGMENT
**Research Status:** DRAFT

## Executive Summary
[To be filled after 01-public-research.md and 02-d2l-angle.md are complete]

## Key Findings
- [ ] Finding 1
- [ ] Finding 2
- [ ] Finding 3

## D2L Opportunity Assessment
See frontmatter in 02-d2l-angle.md for fit / ACV / sales cycle — this section
should restate it in prose once populated.

## Completion Checklist
- [ ] 01-public-research.md fully populated (no [To be researched] left)
- [ ] 02-d2l-angle.md frontmatter fully populated
- [ ] 02-d2l-angle.md prose sections fully populated
- [ ] Proof points checked for freshness (<90 days) and external-use posture
- [ ] Buying committee identified with names/titles
- [ ] Discovery approach outlined

---
**Last Updated:** $TIMESTAMP
EOF
        echo -e "${YELLOW}[process] README.md scaffolded — complete 01/02 docs manually, then run 'validate'${NC}"
    fi

    echo ""
    echo -e "${GREEN}Output: $OUTPUT_DIR${NC}"
    echo "Next: fill in 01-public-research.md and 02-d2l-angle.md, then run:"
    echo "  $0 validate \"$COMPANY_SAFE-$TIMESTAMP\""
}

# ---------------------------------------------------------------------------
cmd_status() {
    FILTER="${1:-}"
    printf "%-45s %-12s %-8s %-10s %s\n" "ACCOUNT" "STAGE" "FIT" "ACV_LOW" "STALE"
    for dir in research/*/; do
        slug=$(basename "$dir")
        [ -n "$FILTER" ] && [[ "$slug" != *"$FILTER"* ]] && continue

        stage="acquired"
        [ -f "$dir/.stage-prepared" ] && stage="prepared"
        [ -f "$dir/.stage-processed" ] && stage="processed"
        [ -f "$dir/.stage-parsed" ] && stage="parsed"
        [ -f "$dir/.stage-rendered" ] && stage="rendered"

        fit="?"; acv="?"
        if [ -f "$dir/02-d2l-angle.md" ]; then
            fit=$(sed -n 's/^fit: *//p' "$dir/02-d2l-angle.md" | head -1)
            acv=$(sed -n 's/^estimated_acv_low: *//p' "$dir/02-d2l-angle.md" | head -1)
        fi

        stale="no"
        if [ -f "$dir/README.md" ]; then
            file_age_days=$(( ( $(date +%s) - $(date -r "$dir/README.md" +%s 2>/dev/null || echo 0) ) / 86400 ))
            [ "$file_age_days" -gt 90 ] && stale="yes (${file_age_days}d)"
        fi

        printf "%-45s %-12s %-8s %-10s %s\n" "$slug" "$stage" "${fit:-?}" "${acv:-?}" "$stale"
    done
}

# ---------------------------------------------------------------------------
cmd_validate() {
    SLUG="$1"
    DIR="research/$SLUG"
    [ -d "$DIR" ] || { echo -e "${RED}Not found: $DIR${NC}"; exit 1; }

    FAIL=0
    check() {
        if eval "$2"; then echo -e "  ${GREEN}✓${NC} $1"; else echo -e "  ${RED}✗${NC} $1"; FAIL=1; fi
    }

    echo -e "${BLUE}Validating $SLUG${NC}"
    check "01-public-research.md exists" "[ -f '$DIR/01-public-research.md' ]"
    check "01-public-research.md has no unresolved [To be researched]" \
        "! grep -q '\[To be researched\]' '$DIR/01-public-research.md' 2>/dev/null"
    check "02-d2l-angle.md exists" "[ -f '$DIR/02-d2l-angle.md' ]"
    check "02-d2l-angle.md frontmatter: fit is not MEDIUM placeholder default" \
        "! grep -q '^fit: MEDIUM$' '$DIR/02-d2l-angle.md' 2>/dev/null || grep -q '^fit: MEDIUM$' '$DIR/02-d2l-angle.md' 2>/dev/null && echo 'review: confirm MEDIUM is intentional, not unset default' >&2; true"
    check "02-d2l-angle.md has at least one vault_source listed" \
        "! grep -q '^vault_sources: \[\]$' '$DIR/02-d2l-angle.md' 2>/dev/null"
    check "README.md exists" "[ -f '$DIR/README.md' ]"

    if [ "$FAIL" -eq 0 ]; then
        touch "$DIR/.stage-processed" "$DIR/.stage-parsed"
        echo -e "${GREEN}All checks passed — marked processed + parsed.${NC}"
    else
        echo -e "${YELLOW}Fix the above before marking this account ready for outreach.${NC}"
    fi
}

# ---------------------------------------------------------------------------
cmd_rollup() {
    echo -e "${BLUE}Portfolio rollup${NC}"
    echo ""
    total_low=0; total_high=0; n=0; stale_n=0
    for dir in research/*/; do
        f="$dir/02-d2l-angle.md"
        [ -f "$f" ] || continue
        n=$((n+1))
        low=$(sed -n 's/^estimated_acv_low: *//p' "$f" | head -1)
        high=$(sed -n 's/^estimated_acv_high: *//p' "$f" | head -1)
        total_low=$((total_low + ${low:-0}))
        total_high=$((total_high + ${high:-0}))
    done
    echo "Accounts researched: $n"
    echo "Pipeline ACV range: \$$total_low - \$$total_high"
    echo ""
    echo "By fit:"
    grep -h '^fit: ' research/*/02-d2l-angle.md 2>/dev/null | sort | uniq -c
}

# ---------------------------------------------------------------------------
case "${1:-}" in
    new)      shift; cmd_new "$@" ;;
    status)   shift; cmd_status "$@" ;;
    validate) shift; cmd_validate "$@" ;;
    rollup)   shift; cmd_rollup "$@" ;;
    *)
        echo "Usage: $0 {new|status|validate|rollup} [args]"
        echo "  new \"Name\" \"Company\" [\"Segment\"]   — scaffold a new account research package"
        echo "  status [\"filter\"]                    — list all accounts and their pipeline stage"
        echo "  validate \"company-slug\"               — run the output-quality checklist as a script"
        echo "  rollup                                — portfolio-level fit/ACV summary"
        exit 1
        ;;
esac
```

## 6. What this changes for you day-to-day

| Before | After |
|---|---|
| `./account-research.sh "Name" "Company" "Segment"` produces templates with the literal string `COMPANY_NAME` in them (bug) | Templates are correctly filled with the real company/contact/date/segment on generation |
| No way to see research-in-flight across accounts without opening each folder | `./account-research.sh status` — one table, all accounts, stage + fit + staleness |
| "Output Quality Checklist" is a manual markdown checklist you eyeball | `./account-research.sh validate <slug>` — scripted, fails loudly, marks stage complete only when clean |
| No portfolio view (total pipeline value, fit distribution) | `./account-research.sh rollup` — greps frontmatter, no manual tallying |
| "Reuse existing research for a segment" = manually remembering/searching | `grep -l 'segment: "..."' research/*/02-d2l-angle.md` now works because frontmatter is structured |
| Staleness (>90-day proof points) is a written rule, never checked | `status` surfaces file age; frontmatter `last_updated` is queryable |
| Re-running the script re-does everything | `.stage-*` markers make each stage idempotent — re-run is a no-op unless you delete the marker |
