# Implementation Lifecycle and Ownership

## Lifecycle

| Phase | Verified purpose | Seller implication |
|---|---|---|
| Pre-implementation | Gather the client's use case, configuration requirements and required setup information through the applicable pre-implementation workbook | Set expectations early and identify the buyer-side owner for accurate inputs |
| 1. Kick-off | Introduce the implementation team, define expectations, scope and timelines, and develop the project plan | Do not create a parallel seller timeline; align commitments to the assigned implementation team |
| 2. Discover and design | Understand the customer ecosystem, motivation, vision and strategic initiatives, then design the solution through consulting sessions | Complete technical and operating-model discovery before treating configuration as settled |
| 3. Train and coach | Develop customer champions in the configured and integrated environment | Identify administrator, instructor and champion participation before launch |
| 4. Prepare for launch | Finalize data loading, outstanding configuration, communications and launch readiness | Treat go-live as a readiness decision with customer responsibilities, not only a date |

## Ownership rules

- Sales qualifies the use case, preserves documented boundaries and completes required handoff inputs.
- Implementation owns the implementation plan and implementation risks.
- Customer Success works alongside implementation but should not control implementation timeline or budget.
- Customer stakeholders own timely decisions, source information, validation, change readiness and the responsibilities assigned in the project.
- Custom, uncertain or nonstandard work requires current scoping before it becomes a proposal commitment.

## Questions to answer before signature

- What is in scope: configuration, content, data, integrations, training and change support?
- Which systems and owners must participate in discovery?
- What customer inputs or workbooks are mandatory?
- What data, content and integration dependencies could block design or launch?
- Who can make decisions and validate acceptance?
- What must be true for administrators, instructors and learners to be ready?

## Safe positioning

“D2L uses a phased implementation approach from pre-implementation discovery through launch readiness. The exact plan, responsibilities and timing depend on the agreed scope and are confirmed with the implementation team.”
