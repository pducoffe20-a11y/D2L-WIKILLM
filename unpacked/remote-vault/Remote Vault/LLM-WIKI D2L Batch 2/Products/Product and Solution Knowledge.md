## Verified product and service facts

### Commerce

The current Product Resources page describes Course Merchant as a front-end course catalogue with payments, registration and automated enrolment into Brightspace, including SSO access. It is generally available, has documented regional and language constraints, and is positioned for external users, fee-based courses and a branded commerce experience.

The same page explicitly says Course Merchant is not intended for employee training and is not intended for the K-12 education use case, although K-12 professional learning requires exploration. This boundary must be retained in qualification.

### Corporate training fit

The Corporate Use Cases page separates training requirements by:

- Training model: course completion, certification/qualification, or talent/skills.
- Delivery scope: internal employees, external trainees, or extended enterprise.
- Additional factors: government, distributed administration, and entitlement/pricing models.

It states that Brightspace alone does not usually meet many external, credentialing or skills scenarios. A third-party system or customer system of record may be required. This is a fit check, not a negative universal claim.

### Integrations

D2L Link documentation includes workflow-specific connectors rather than a blanket “integrates with everything” claim. One documented pattern is issuing a mapped Credly badge after a Brightspace course completion. Named integrations and data flows must be verified individually.

### Administration services

The LAM pitch deck documents Brightspace and Course Merchant administration support including users, roles, permissions, tools, configurations, course shells, content copying, integration setup, data guidance and change tracking. It also distinguishes package scope and states that complex data work may require Data Solutions Consulting.

### Onboarding and implementation

The Customer Onboarding Program covers the customer journey through go-live. The New Logo workflow separates implementation responsibility from customer-success relationship work. Sellers and customer-success roles must not control implementation scope, project timeline or budget unless the responsible implementation process establishes it.

### Current demo and release boundaries

The Fusion 2026 demo page distinguishes available features from unreleased or non-demoable items. A screenshot or enablement mention is not proof of general availability. Demo status, entitlement and product status must be checked together.

## Claims not verified by this source set

- Legal accessibility compliance for a specific customer or jurisdiction
- Exhaustive behavior for every mobile workflow
- Every possible integration workflow, object and direction
- A complete credentialing and renewal workflow
- Pricing, packaging, roadmap, security commitments or implementation timelines
